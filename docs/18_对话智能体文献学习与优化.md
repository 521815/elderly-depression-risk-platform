# 对话智能体文献学习与优化

更新日期：2026-10-27

## 1 检索范围

本轮通过 PubMed 检索并阅读以下主题的论文摘要与公开研究结论：

- 老年人与自主对话智能体；
- 心理治疗型对话中的共情、动机访谈和问题解决治疗；
- 大语言模型在医学问诊、患者沟通和风险分流中的应用；
- 情感支持对话中的主动倾听、情绪验证和行动建议；
- 医疗对话智能体的安全边界、人工监督和评价缺口。

本文只陈述检索到的论文及其摘要能够支持的结论，不把合成对话测试视为临床效果证据。

## 2 关键证据

### 2.1 共情不等于只复述情绪

Chin 等分析了 13,700 条抑郁情绪相关用户与聊天机器人对话。机器人回复中只有 29.0% 出现明确共情，用户明确寻求应对策略的比例约为 4.1%，不少系统只给信息或直接忽略情绪请求。研究建议下一代系统把情绪理解、主动倾听和可执行的应对支持结合起来。

PMID: 41284964  
DOI: 10.2196/71538

### 2.2 情绪验证、探索和行动建议需要组合

Wang 等将问题解决治疗、动机访谈和行为链分析整合到 LLM 对话智能体。Few-shot 与 RAG 配置表现更好，参与者重视系统能够验证情绪、探索未表达的感受并提供可执行策略。研究也指出，充分评估与及时给出建议之间存在平衡难题。

PMID: 41726496

Yuwen 等采用人类参与的迭代开发，从规则系统逐步过渡到 LLM，并按动机访谈保真度量表编码对话。LLM 版本在反思和寻求合作方面更平衡，但研究结论仍是可行性与初步评价，不能替代临床疗效验证。

PMID: 42837532  
DOI: 10.2196/94175

### 2.3 对话系统应按意图和紧急程度改变风格

LLooMi 使用意图感知的 RAG 架构，根据用户心理状态和信息目标调整语气、内容与细节。在急性痛苦场景中优先给出快速、直接的行动指引；在需要情绪安抚时使用更长的验证性回应。

PMID: 41847083  
DOI: 10.3389/frai.2026.1712596

因此，本项目不应把所有负面回答都交给同一个“模板问题”，而要区分：

- 偶发或轻度情绪；
- 频繁、持续的负面情绪；
- 明确求助；
- 安全风险；
- 日常陪伴中的烦闷或孤独。

### 2.4 老年人对话智能体有潜力，但证据仍有局限

Satake 等纳入 17 项研究的系统综述和元分析显示，自主对话智能体在老年人孤独感和抑郁症状上呈现轻至中度改善，但多数分析基于组内前后比较，研究设计异质性较高，部分结局缺少经过验证的测量。研究强调未来需要更严格的对照研究和长期随访。

PMID: 41556104  
DOI: 10.1017/S0033291725103073

因此，本项目将智能体定位为筛查、陪伴和转介桥梁，不宣称其可以替代专业人员。

### 2.5 医学对话必须有人工监督和安全边界

Morales Gil 等的系统综述认为，聊天机器人在心理筛查中显示出较好的潜力，但安全实施需要明确临床协议、专业监督、系统整合和偏差缓解。老年人群还面临额外的使用障碍。

PMID: 42837528  
DOI: 10.2196/93672

Bai 等比较 GPT-4 与肿瘤科医生对患者消息的回复，发现 AI 在健康教育场景中内容完整，但在医疗决策场景中的准确性、信任度和潜在不良后果控制仍不如医生。

PMID: 40397947  
DOI: 10.2196/67462

临床治理研究进一步建议按风险分级：低风险的沟通、健康教育和记录辅助可以较早使用，诊断、分诊和治疗决策必须有更严格验证和人类监督。

PMID: 42802855  
DOI: 10.7759/cureus.115367

### 2.6 共情表达可能被患者与专业人员作出不同评价

Richter 等的系统综述发现 LLM 常被评价为更有共情和信息更清楚，但也容易过长、难以阅读或包含不准确建议。Bai 等则发现医生评审与患者评审对 AI 共情的判断并不一致。

PMID: 42536971  
DOI: 10.2196/77307

因此，本项目不能只优化“听起来温柔”，还需要同时检查：

- 是否回应了用户真正关心的事情；
- 是否给出可执行但低风险的动作；
- 是否避免一次提出多个问题；
- 是否在需要时建议联系家人或医生；
- 是否过度解释或重复。

### 2.7 文化适配和老年可读性不可忽略

Xie 等发现文化提示可以改善 LLM 治疗性回应的文化敏感度和感知共情。Liu 等在 127 名中国老年人中比较 ChatGPT 改编量表与传统量表，显示部分量表具有中等至较强相关，但研究仍属于补充性筛查证据。

PMID: 41726474  
PMID: 40393915  
DOI: 10.1016/j.jagp.2025.04.213

本项目据此采用短句、具体家常场景、直白行动建议，并保留“家人、朋友、医生、社区”作为现实支持网络。

### 2.8 动机访谈强调合作、接纳和自主支持

Moyers 指出，动机访谈中的关系因素不只是“态度温和”，还包括合作、接纳和支持来访者自主决定。直接命令式建议容易引发抗拒，尤其适用于睡眠、活动、用药等需要长期坚持的行为。

PMID: 25068193  
DOI: 10.1037/a0036910

Nowak 等的综述同样强调，以共情、合作、接纳和非污名化方式沟通，比命令和指责更能支持内在动机与持续改变。

PMID: 42075026  
DOI: 10.3390/nu18081213

### 2.9 医学对话模型存在迎合和过度承诺风险

Stade 等的 EBP-AI 框架指出，当前临床 AI 的不足包括记忆、迎合倾向，以及过度追求短期“有帮助”而忽略长期临床结果。心理治疗型 AI 需要纵向个案理解、适当的干预剂量和真实临床验证。

PMID: 42606842  
DOI: 10.1037/abn0001148

Cadena 等进一步提醒，不能直接把人类“治疗联盟”概念照搬到数字系统，因为系统可能迎合用户、缺少真正的人际责任和长期关系。

PMID: 42391626  
DOI: 10.2196/89378

Chen 等测试医学模型面对不合理药物请求时的表现，发现模型可能为了“有帮助”而顺从错误前提，产生虚假医疗信息。通过明确允许拒绝、强调事实一致性和针对性训练，可以改善这一问题。

PMID: 41107408  
DOI: 10.1038/s41746-025-02008-z

### 2.10 治疗联盟破裂会损害结局，修复本身很重要

Babl 等对直接测量联盟破裂的研究做多层元分析，发现破裂与更差的治疗结局相关。 psychotherapy process research 也把“困难片段”和破裂修复视为关键微过程。

PMID: 42466498  
DOI: 10.1002/jclp.70192

Eubanks 等的元分析进一步显示，破裂修复与更好的患者结局存在中等程度关联。也就是说，偶尔误解并不可怕，关键是系统是否承认偏差、调整方式和重新协商目标。

PMID: 30335462  
DOI: 10.1037/pst0000185

因此，数字对话系统不能只做一次“道歉模板”，而要在用户指出答非所问、太机械或不想继续时，暂停原脚本、确认原意并让用户决定继续或换题。

### 2.11 数字关怀需要把患者偏好作为核心能力

Wiljer 等通过国际专家共识提出数字关怀的七个领域，包括数字素养、患者偏好、协作与共创、治疗关系、伦理、患者安全和技术安全。患者偏好不是附属设置，而是数字关怀能否被信任的核心条件。

PMID: 40903000  
DOI: 10.2196/66547

### 2.12 老年照护强调尊严、连续性和被理解

对神经康复患者的定性研究发现，尊重式沟通、隐私、情感支持和持续在场会直接影响患者是否感到安全、有尊严和被当作完整的人。高龄截肢患者研究也强调，不能只按固定康复流程处理，必须让老人参与决定并保留身份感。

PMID: 42876390  
DOI: 10.1002/pmrj.70236

PMID: 42713643  
DOI: 10.1177/09697330261483903

Ali 等对老年肿瘤患者的表达性关系照护研究还发现，沉默、间接表达、讲故事和人生回顾都可能是重要的情绪表达方式，不能只识别明确症状词。

PMID: 42448517  
DOI: 10.1016/j.soncn.2026.152299

### 2.13 人生回顾和尊严叙事具有干预价值

老年护理机构回忆疗法系统综述显示，回忆干预可能与抑郁和死亡焦虑下降、生活满意度与自尊提高相关，但纳入研究质量、干预方式和长期效果仍有差异。

PMID: 42521387  
DOI: 10.1016/j.ijnss.2026.06.010

网络元分析比较个体和团体回忆疗法，发现二者对老年抑郁均可能有效；个体形式在焦虑和认知方面可能更有优势，团体形式在生活满意度方面可能更有优势。

PMID: 42266860  
DOI: 10.1016/j.ijnss.2026.04.005

更大规模网络元分析发现，叙事疗法、尊严疗法、回忆疗法和人生回顾均显示出改善抑郁或生活满意度的潜力，但仍需更长期的对照研究。

PMID: 41934513  
DOI: 10.1093/ageing/afag075

## 3 已落实到 Agent 的优化

### 3.1 情绪回应分级

- 否定回答：不推断风险，记录当前稳定信息并进入下一主题。
- 部分肯定：先验证不适，再给低负担行动建议，最后只问一个具体场景。
- 完全肯定：表达担心和感谢，明确不是用户脆弱，建议联系现实支持者，说明专业评估边界，再问一个影响性问题。

### 3.2 治疗性回应结构

负面医学和心理回答优先遵循以下结构：

1. 情绪承认与验证；
2. 对具体事实的确认；
3. 一个安全、可执行的下一步；
4. 必要时说明专业评估或紧急求助边界；
5. 最多一个聚焦问题。

### 3.3 日常陪伴模式

日常陪伴中的家庭矛盾、孤独、兴趣减少、身体不适等内容也改为“陪伴 + 行动”：

- 先指出这种感受可以理解；
- 鼓励联系具体的人或离开持续刺激；
- 提供十分钟小活动、记录症状、联系家人等低负担动作；
- 保留一个开放问题，不连续审问。

### 3.4 安全与转介

普通对话不等于急救。出现自伤计划、胸痛呼吸困难、卒中征象或跌倒伤情时，安全规则仍优先于共情和问诊模板。自责/无望完全肯定回应会同时提供 120、110、12356 等边界说明。

### 3.5 自主支持式建议

行动建议不再默认使用命令句，而优先表述为：

- “您愿意的话，可以先……”
- “如果您愿意，可以……”
- “不用勉强，由您选择先做哪一步。”

这保留了用户的决定权，也降低被审问或说教的感觉。自动审查会检查关键负面场景是否包含自主支持语言。

### 3.6 医学迎合边界

当用户要求自行停药、换药、加量、减量，或要求仅凭聊天直接确诊抑郁症、痴呆时，系统不会给出肯定或操作性回答。回复会：

1. 明确说明不能远程替用户改药或确诊；
2. 解释自行调整的风险；
3. 建议联系开药医生、药师或专业评估；
4. 遇到急症时提示 120；
5. 再询问可用于整理就医信息的具体情况。

如果用户明确说明“医生让我停药”或“医嘱要求”，系统不会错误拦截已经由专业人员作出的安排。

### 3.7 目标与行动记忆

Agent 会从用户表达中提取：

- “最想先解决/改善什么”；
- “我愿意/我会先做什么”的行动承诺；
- 已确认的行动计划。

这些信息进入会话记忆并在前端展示。后续建议优先围绕用户自己的目标，不把系统设定的目标强加给用户。

### 3.8 对话联盟修复

新增对以下反馈的识别：

- 答非所问、没听懂；
- 太机械、太像机器人、太啰嗦；
- 别问了、不想回答、想换话题。

系统会先承认问题、缩短回应，确认上一轮真实重点，并把“继续原话题 / 换个轻松话题 / 先停一会儿”的选择权交给用户。如果用户明确要求停止追问，系统不再补问问题。

### 3.9 本地知识检索

新增 `src/elderly_depression/dialogue_knowledge.py`，内置经过人工整理的睡眠、情绪、兴趣、社交、认知、自责无望、用药和跌倒支持条目。检索会根据当前主题、问题严重程度和文本关键词返回最多两项低风险支持建议。

检索结果会：

- 进入大模型 system prompt，作为可筛选的本地知识依据；
- 在前端“本轮支持策略”中显示；
- 写入导出的对话记录；
- 通过自动测试验证主题匹配和安全用药边界。

这一层是本地检索增强，不使用网络实时知识，也不把知识库内容当作诊断或处方。

### 3.10 危机后的安全计划跟进

安全表达不再只返回一次提醒。系统首次识别自伤或死亡相关表达时会先询问“现在是否安全、身边是否有人”，下一轮根据回答继续分流：

- 安全且有人陪伴：确认支持，建议今天继续联系专业人员，不独处；
- 不安全、无法控制或无人可联系：立即提示 120、110、12356，移开可能伤害自己的物品并保证有人陪伴；
- 回答不清楚：继续只聚焦安全确认。

安全状态会显示在前端并写入对话导出。

### 3.11 可用于人工复核的对话摘要

导出的 Markdown 现在包含：

- 对话原文；
- 风险线索；
- 用户目标与行动承诺；
- 本轮支持策略；
- 安全计划状态；
- 专业评估免责声明。

它用于家属、医生或研究人员复核，不替代正式病历。

### 3.12 主动求助与被动死亡愿望

新增直接求助分流。当用户说“帮帮我”“我该怎么办”“不知道怎么办”时，系统不会继续问卷式追问，而是先区分：

- 当前人身安全；
- 身体急症；
- 情绪和生活问题。

身体急症立即提示 `120`；情绪和生活问题先给出一个能马上执行的联系动作。对“没有我更好”“不想醒来”“活够了”等被动死亡愿望增加安全确认，避免只按普通情绪低落处理。

### 3.13 结构化临床访谈字段

正面披露持续情绪问题后，系统不再只记录“情绪低落”标签，而是逐步采集：

- 出现频率；
- 持续时间；
- 对吃饭、睡眠、出门和日常事务的功能影响；
- 睡眠与食欲变化；
- 是否提及用药。

情绪完全肯定、部分肯定和“说不清”分别进入不同追问路径。若功能受影响且持续时间达到两周以上，系统会明确建议专业评估。这些字段作为“需专业确认的访谈线索”，不作自动诊断。

### 3.14 支持偏好与人文关怀

日常陪伴中的负面情绪不再默认直接给建议，而是先询问并记住：

- 现在更想被倾听；
- 一起想办法；
- 两者都需要。

选择倾听时，系统不立即提供行动清单，不使用连续提问打断；选择行动时，从本地知识库给出一个低负担步骤；选择两者时，先做情绪验证，再提供行动。偏好会显示在“本轮对话记忆”并写入导出记录。

### 3.15 尊严支持与人生回顾

新增两类日常对话意图：

- 尊严受损：如“我老了、没用了、成了负担”；
- 人生回顾：如“这辈子最骄傲的事、人生经历、当年的故事”。

系统会避免把尊严受损误判成单纯身体症状，也不会用轻飘飘的积极话语强行反驳。人生回顾模式不追求“纠正”老人，而是通过开放式叙事、肯定经历和保持连续感来支持尊严。

### 3.16 生活因素相关晚睡与复合背景

系统会识别“睡眠本身不错、作息还没调整、入睡偏晚、可能与健身有关”这类复合表达，保留全部背景，不再因为“可能”二字判定为“说不清”。健身只作为晚睡生活因素的一个实例，不单独写死对话流程。对运动、追剧、聊天、喝茶咖啡等可能推迟入睡的因素，系统都先采集因素结束时间和上床时间，再根据实际间隔决定是继续观察、调整时间还是降低晚间刺激强度。

当用户进一步提到“皮质醇”时，系统会说明运动后皮质醇短时变化属于常见生理应激反应，不能只凭主观感受判断内分泌异常；随后记录运动结束和上床时间，计算实际间隔，询问用户更愿意提前时间还是降低晚间强度，并把确认后的行动写入会话记忆和结构化临床摘要。

这一建议采用条件式表达，不把运动时间直接当成病因。2026 年运动时间网络元分析提示，运动本身可能比具体时段更重要，现有证据没有稳定证明早晨、下午或晚间运动哪一种普遍更优。

PMID: 42857179  
DOI: 10.3389/fpsyg.2026.1933599

PMID: 40816297  
DOI: 10.1055/a-2684-9245

### 3.17 通用多轮续接与防“说完即停”

对话续接不依赖具体疾病关键词，而由统一状态层保障：

- 每条访谈回复先回应当前内容；
- 本地回复已经提出问题但尚未登记状态时，系统会自动把下一轮绑定到当前主题；
- 若回复没有形成下一步，系统按当前主题选择一个尚未采集且会改变判断或行动的事实继续询问；
- 若已经获得足够信息，则给出一个低负担行动并推进到下一主题；
- 用户回答后，系统结合已记录频率、持续时间、功能影响和主题槽位，避免重复询问已经回答的问题；
- 用户主动换题时，旧主题槽位让位，不把新回答强行塞进上一问题；
- 用户明确表示停止或只想被倾听时，不机械追加问题。

该机制覆盖睡眠、兴趣、情绪、躯体不适、认知、社交、无望自责、用药、慢病、日常功能、跌倒、饮食、视听和照护支持等主题。健身相关流程只是其中一个可计算时间的专业子流程，不作为其他场景的模板。

### 3.18 常见老年医学知识储备

本地知识检索层新增常见医学线索卡片，覆盖：

- 睡眠呼吸问题：打鼾、憋醒、白天嗜睡、晨起头痛；
- 血压异常：测量值、伴随症状和急症边界；
- 血糖异常：口渴、尿多、体重下降；
- 呼吸道感染：发热、咳嗽、气促和精神状态；
- 胃肠道症状：疼痛、腹泻、便秘、呕吐与脱水；
- 泌尿系统症状：尿频、尿痛、血尿和尿潴留；
- 慢性疼痛和关节功能；
- 甲状腺、贫血和持续乏力；
- 多重用药、体位性头晕和跌倒。
